# Сеть Объекта №6

Статическое веб-приложение: сеть архивов, терминал Четвёртой Передачи, мини-игры взлома и газетный микроридер.

## Локальный запуск

Нужен Node.js 22 или новее. Внешних npm-зависимостей нет.

```sh
npm run build
npm run preview
```

Откройте http://127.0.0.1:4173. После изменения газет повторите сборку.

## Загрузка на GitHub и GitHub Pages

1. Создайте репозиторий с основной веткой `main`.
2. Загрузите содержимое этой папки, включая `.github/workflows/pages.yml`, `scripts` и `dist`. Не загружайте внешнюю папку проекта с архивами публикаций.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Отправьте изменения в `main` или запустите **Actions → Deploy GitHub Pages → Run workflow**.
5. Дождитесь успешного выполнения. Адрес сайта появится в **Settings → Pages** и в результате workflow.

Workflow собирает каталог газет и страницу письма, затем публикует только `dist`. Пути ресурсов относительные: сайт поддерживает адрес вида `https://USERNAME.github.io/REPOSITORY/`.

Если рабочая ветка называется иначе, измените `branches: [main]` в workflow. Настройки существующего хостинга в `.openai/hosting.json` не используются GitHub Pages и не попадают в публикуемый артефакт.

## Газеты

Добавляйте или удаляйте изображения в `dist/assets/microreader/`. Поддерживаются PNG, JPG, JPEG, WebP, GIF и AVIF. Файлы сортируются по имени с учётом чисел; имена используются как подписи. После push в `main` каталог и счётчики обновляются автоматически при сборке.

## Структура

- `dist/` — HTML, CSS, JavaScript и изображения сайта.
- `scripts/build-microreader.mjs` — автоматический каталог газет и счётчики.
- `scripts/build-letter.mjs` — сборка защищённой страницы письма из шаблона архива и текста в `dist/fourth.js`.
- `serve.mjs` — локальный сервер предварительного просмотра.

## Игровой доступ

Для локального чтения статусов из Supabase скопируйте `.env.example` в `.env`, задайте `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` из окна **Connect**, затем запустите `npm run preview`. Сборка GitHub Pages уже настроена на проект «Объект №6». Для смены проекта задайте обе одноимённые переменные репозитория в **Settings → Secrets and variables → Actions → Variables**. Сборка публикует только публичный ключ.

При запуске сайт читает `object6_structures` через Data API. Когда подключение недоступно, используются статусы из HTML. Состояние электроэнергии рассчитывается игрой с реактором.

Ключи игровых архивов и сценарии взлома работают в браузере. Исходный код и содержимое статических страниц доступны посетителям.

## Аккаунты и сообщения

Аккаунты и сообщения используют таблицы `object6_users` и `object6_messages` в проекте Supabase, указанном в `SUPABASE_URL`. Роли хранятся в текстовом поле `role` через запятую. Сообщения открываются только в сессии получателя. После открытия `unread` меняется с `Yes` на `No`.

Регистрация доступна из окна входа. Для входа используется имя и отдельный пароль. Слово для взлома необязательно и сохраняется в `hack_word_hash` в виде хеша. Сессия сохраняется при обновлении вкладки, истекает через 24 часа и закрывается командой «Выйти».

Для профиля, созданного до миграции, задайте первоначальный пароль в SQL Editor. Замените UUID и пароль в примере. Повторного создания профиля не требуется.

```sql
insert into object6_private.credentials (user_uuid, password_hash)
values (
  '00000000-0000-0000-0000-000000000000',
  extensions.crypt('ЗАМЕНИТЕ-ПАРОЛЬ', extensions.gen_salt('bf', 10))
);
```
