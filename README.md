# Сеть Объекта №6

Статическое веб-приложение: сеть архивов, терминал Четвёртой Передачи, мини-игры взлома и газетный микроридер.

## Локальный запуск

Нужен Node.js 22 или новее. Внешних npm-зависимостей нет.

```sh
npm run preview
```

Откройте http://127.0.0.1:4173. Команда собирает сайт и запускает локальный сервер. После правок в исходниках выполните `npm run build` или перезапустите предпросмотр.

## Загрузка на GitHub и GitHub Pages

1. Создайте репозиторий с основной веткой `main`.
2. Загрузите исходники этой папки, включая `.github/workflows/pages.yml`, `src/`, `templates/` и `scripts/`. Папка `dist/` создаётся автоматически.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Отправьте изменения в `main` или запустите **Actions → Deploy GitHub Pages → Run workflow**.
5. Дождитесь успешного выполнения. Адрес сайта появится в **Settings → Pages** и в результате workflow.

Workflow собирает сайт и публикует `dist/`. Относительные пути позволяют открывать сайт под префиксом репозитория, например `https://USERNAME.github.io/REPOSITORY/`.

Если рабочая ветка называется иначе, измените `branches: [main]` в workflow. Настройки существующего хостинга в `.openai/hosting.json` не используются GitHub Pages и не попадают в публикуемый артефакт.

## Газеты

Добавляйте или удаляйте изображения в `src/assets/microreader/`. Поддерживаются PNG, JPG, JPEG, WebP, GIF и AVIF. Сборка сортирует файлы по имени с учётом чисел и генерирует каталог, из которого микроридер берёт подписи и счётчик.

## Структура

- `src/index.html` — разметка главной страницы, включая сеть, аккаунты, почту и досуг.
- `src/network/` — архив, карта и реактор. Тексты документов находятся в `archive-documents.js`.
- `src/account/` — вход, профиль, уведомления и сообщения.
- `src/medicine.html` и `src/medicine/` — Медблок, приём и печать карты пациента.
- `src/leisure/` и `src/microreader/` — игры, таблица результатов и интерфейс чтения газет.
- `src/fourth.html`, `src/g4/` и `templates/g4/` — внешняя сеть G4, параметры игровых головоломок, общий шаблон доступа и тексты закрытого архива и письма.
- `src/shared/` — тема, клавиатура, звуки и HTTP-клиент Supabase.
- `scripts/build.mjs` — сборка сайта в `dist/`. `serve.mjs` раздаёт этот каталог на локальном сервере.
- `supabase/migrations/` — миграции функций и таблиц Supabase.

## Игровой доступ

Для локального чтения статусов из Supabase скопируйте `.env.example` в `.env`, задайте `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` из окна **Connect**, затем запустите `npm run preview`. Сборка GitHub Pages уже настроена на проект «Объект №6». Для смены проекта задайте обе одноимённые переменные репозитория в **Settings → Secrets and variables → Actions → Variables**. Сборка публикует только публичный ключ.

При запуске сайт читает `object6_structures` через Data API. Когда подключение недоступно, используются статусы из HTML. Состояние электроэнергии рассчитывается игрой с реактором.

Ключи игровых архивов и сценарии взлома работают в браузере. Исходный код и содержимое статических страниц доступны посетителям.

## Аккаунты и сообщения

Аккаунты и сообщения используют таблицы `object6_users` и `object6_messages` в проекте Supabase, указанном в `SUPABASE_URL`. Роли хранятся в текстовом поле `role` через запятую. Сообщения открываются только в сессии получателя. После открытия `unread` меняется с `Yes` на `No`.

Регистрация доступна из окна входа. Для входа используется имя и отдельный пароль. Слово для взлома необязательно и сохраняется в `hack_word_hash` в виде хеша. Сессия сохраняется при обновлении вкладки, истекает через 24 часа и закрывается командой «Выйти».

Для профиля, созданного до миграции, задайте первоначальный пароль в SQL Editor. Замените UUID и пароль в примере. Повторного создания профиля не требуется.

```sql
insert into object6_private.credentials (user_uuid, password_hash)
values (
  '00000000-0000-0000-0000-000000000000',
  extensions.crypt('ЗАМЕНИТЕ-ПАРОЛЬ', extensions.gen_salt('bf', 10))
);
```

## Медблок

В Supabase после настройки аккаунтов примените по порядку миграции
`20261124090000_object6_medicine.sql`, `20261124090100_object6_diseases_seed.sql`
`20261124090200_object6_medicine_overdue_thresholds.sql` и
`20261124090300_object6_medicine_analysis.sql` и
`20261124090400_object6_medicine_case_status.sql` и
`20261124090500_object6_medicine_visibility.sql`.
Перед последней миграцией проверьте текущих обладателей ролей ADMIN и MEDIC
запросом `supabase/manual/medicine_staff_review.sql`. Ранее игроки могли
выбирать ADMIN при регистрации. Оставьте эти роли у тех, кому положен доступ к реестру.

Справочник болезней открыт всем. Вошедший игрок видит свою карту.
Роли ADMIN и MEDIC дают доступ ко всему реестру, лаборатории и регистрации
поступлений. Статус диагноза может изменить пациент или пользователь с
одной из этих ролей. Временные аккаунты можно создать запросом
`supabase/manual/medicine_test_users.sql`.

Кнопка «Печать карты» открывает режим печати браузера. В нём можно выбрать
принтер или сохранить карту в PDF.
